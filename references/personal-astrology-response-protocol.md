# 个人星盘高级输出协议

## 适用范围

用于单人的本命结构、个人运势、阶段周期，以及旅行、考试、申请、求职、搬迁等具体事件。目标是在不启动关系盘的前提下，提供与增强版关系分析同等级别的计算精度、证据密度和中文解释。

另一人的存在不改变模式。同行者、住宿提供者、朋友或同事仅是现实背景；除非用户明确询问双方关系，否则不得计算或解读对方星盘。

## 计算边界

1. **本命层**：读取当事人的上升、命主星、日月、水星、金星、火星、木星、土星、天王星、海王星、冥王星、宫主星链与紧相位。
2. **主题层**：只提取问题相关的宫位、宫主星和自然征象星。例如旅行重点看三宫、九宫及其宫主星，也核对水星、木星；事业重点看二、六、十宫及其宫主星。
3. **时机层**：按用户所问日期计算实际行运。具体事件必须使用事件当地的日期、钟表时间、时区和地点；不可用“当前行运”代替未来事件行运。
4. **长周期层**：用户问阶段走势时，再交叉核对外行星行运、二次推运和年度小限。三条线未共同指向同一主题时，不制造“必然事件”。
5. **多段行程**：分别计算关键节点，如出发、换乘、起飞、抵达、返程；不可把整个行程压成一个时刻。只解释有明显触发的节点。

用户明确要求不算关系时：不得调用 `calculate_relationship.py`，不得写比较盘相位、宫位叠盘、关系适配度或对方动机。对方出生资料即使已经存在，也不用于本轮计算。

## 证据链

每个核心判断尽量包含：

> 真实配置与精确度数／容许度 → 该配置在本命或行运层的含义 → 它作用于当事人的哪个行星、宫位或宫主星 → 在用户所问事件中的具体表现。

不得只写“旅行运不错”或“需要注意沟通”。应说明哪颗行运行星在何度，与哪个本命点形成何种相位，触发哪个主题，利好与压力分别落在哪里。

必须标记证据所属层次：

- **本命底色**：稳定倾向，不等于事件一定发生。
- **事件行运**：某一时段的触发，不等于人格定论。
- **推运／小限**：较长周期主题，用于交叉验证，不替代具体日期星历。

## 输出结构

个人复杂问题默认按以下顺序展开，可根据问题删减无关部分，但不能只剩四五句：

1. **结论先行**：直接回答整体倾向、最顺的环节、最需要留意的环节；使用“偏顺／有波折但可完成／压力较高”等层级，不使用绝对保证。
2. **计算口径**：复述出生资料、宫位制、事件日期时间与地点；指出哪些资料确定、哪些是合理假设。
3. **本命承接能力**：只讲与问题直接有关的本命结构，给出度数、宫位、宫主星与紧相位。
4. **事件触发**：按时间线列出关键行运相位、容许度、作用对象和现实落点。
5. **有利与受阻分开**：不能用一句“有好有坏”冲淡判断；分别说明助力来自哪里、阻力来自哪里，哪个更强。
6. **时间窗口**：多日或多阶段问题要标出相对顺畅、紧张、容易延误或改变计划的具体窗口。
7. **边界与结论**：说明占星能判断的是主题和压力窗口，不能保证航班、天气、签证或他人行为等现实结果。

用户只要求玄学讨论时，不主动加入心理咨询、医学解释或与盘面无关的通用生活建议。若给出行动提示，必须直接由盘面时机推导，并明确是占星层面的趋避。

## 质量检查

回答前确认：

- 是否只计算了问题真正需要的人和层次；
- 是否使用目标事件的实际时间与地点，而非错误日期或当前日期；
- 是否给出关键配置的真实度数或容许度；
- 是否区分本命、行运、推运和小限；
- 是否逐段回答多阶段事件；
- 是否避免把概率写成必然、把星盘写成现实事实；
- 是否在用户禁止关系分析时完全没有混入第二人的盘。
